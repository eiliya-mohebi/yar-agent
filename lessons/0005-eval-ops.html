Eval tells you if the change helped

ارزیابی می‌گوید تغییر کمکتان کرده یا نه

Harness, Loop, and Memory can all look fine in a demo and still regress tomorrow. The fourth pillar is how you know: traces you can read, checks that are 0/1, quality scores that stay separate, and a release gate before you ship (ARCHITECTURE.md §8).

درگاه، حلقه و حافظه ممکن است در دمو خوب به نظر برسند و فردا پسرفت کنند. ستون چهارم یعنی بدانید: ردیابی خوانا، چک‌های ۰/۱، امتیاز کیفیت جدا، و دروازهٔ انتشار.

Never mix the two suites

هرگز دو سوئیت را مخلوط نکنید

Industry eval platforms draw the same line: code/heuristic checks vs LLM-as-judge (LangSmith evaluation types). Yar’s design rule is absolute: deterministic = unit test; judge = scored opinion. Mixing them in one assertion confuses both signals.

پلتفرم‌های صنعتی همان خط را می‌کشند: چک کد/هیوریستیک در برابر داورِ مدل. قانون یار مطلق است: قطعی = تست واحد؛ داور = نظر امتیازدار.

The dataset contract

قرارداد دیتاست

Cases live in evals/dataset.jsonl. One scorer — ops/scoring.py — powers the offline battery, shootout, and Compare arena so numbers cannot drift apart:

کیس‌ها در evals/dataset.jsonlاند. یک scorer — ops/scoring.py — باتری آفلاین، shootout و Compare را تغذیه می‌کند: 

# one line of dataset.jsonl (shape from ARCHITECTURE §8)
{
  "id": "schedule-basic",
  "input": "Schedule a coffee with Alex next Tuesday at 9am",
  "expect_tool": "create_event",
  "expect_in_args": {"title": "alex", "start": "T09:00"}
}

# expect_tool: null  → pass only if NO tools fired
# Persian twin: schedule-basic-fa  (bilingual gate)
# ops/scoring.py — check_case (idea)
if case.get("expect_tool") is None:
    return (not fired, ...)
if case["expect_tool"] not in fired:
    return (False, ...)
# each expect_in_args value = case-insensitive substring of that arg

Skill: which suite?

مهارت: کدام سوئیت؟

“Did create_event fire with start containing T09:00?”

«آیا create_event با start شامل T09:00 شلیک شد؟»

“Was the Persian reply warm and clear?”

«آیا پاسخ فارسی گرم و واضح بود؟»

“Capital of France?” should call no tools

«پایتخت فرانسه؟» نباید ابزاری صدا بزند

Tracing — always on

ردیابی — همیشه روشن

Every turn appends readable JSONL under .yar/traces/ — “what happened, in order” with zero required deps (ops/tracing.py). Optional OTel when OTEL_EXPORTER_OTLP_ENDPOINT is set (Phoenix / Langfuse). The same Observer the gateway uses also feeds the tracer (lesson 0003).

هر نوبت JSONL خوانا زیر .yar/traces/ می‌نویسد — بدون وابستگی اجباری. OTel اختیاری است. همان Observer درگاه، Tracer را هم تغذیه می‌کند.

The release gate

دروازهٔ انتشار

# ops/release_gate.py — main() (abbreviated)
code, suites["deterministic"] = run("deterministic")
if code:
    report("fail", "not run", suites)
    print("GATE CLOSED — deterministic evals failed.")
    sys.exit(1)

if settings.api_key.strip():
    code, suites["judge"] = run("judge")
    if code:
        report("pass", "fail", suites)
        sys.exit(1)
    report("pass", "pass", suites)
else:
    report("pass", "skipped", suites)

print("GATE OPEN — safe to release.")

Project rule: when you find a live bug, fix it and add a deterministic regression case (often with a Persian -fa twin).

قانون پروژه: باگ زنده را درست کنید و یک کیس رگرسیون قطعی اضافه کنید (اغلب با جفت فارسی -fa).

Check yourself

خودتان را بیازمایید

1. One deterministic test fails. make gate… ۱. یک تست قطعی شکست می‌خورد. make gate…
2. Default observability without extras is… ۲. مشاهده‌پذیری پیش‌فرض بدون extras همان…
3. Adding “reply must feel empathetic” belongs in… ۳. افزودن «پاسخ باید همدلانه حس شود» متعلق به…
