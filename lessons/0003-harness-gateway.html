The harness only moves text

درگاه فقط متن را جابه‌جا می‌کند

After the loop, the next clarity win is the boundary around it. A gateway accepts user text and returns a reply string. It does not plan, call tools, or consolidate memory — that stays in Yar.respond() and the pillars behind it (ARCHITECTURE.md §1).

بعد از حلقه، برد بعدی مرز اطراف آن است. درگاه متن کاربر را می‌گیرد و رشتهٔ پاسخ را برمی‌گرداند. برنامه‌ریزی، ابزار، و تجمیع حافظه کار او نیست.

Why this pillar exists

چرا این ستون وجود دارد

Anthropic’s advice for agents is to keep systems simple and transparent, and to treat the agent–computer interface carefully (Building effective agents). Yar’s teaching move: put every surface (CLI, SPA, future adapters) in the same thin role — I/O only — so you can swap the surface without rewriting the loop. The docs say it flatly: “Gateways only move text; the loop stays ~95 lines.”

توصیهٔ Anthropic: سامانه را ساده و شفاف نگه دارید. حرکت آموزشی یار: هر سطح (CLI، SPA، آداپترهای بعدی) همان نقش نازک را دارد — فقط I/O — تا بتوانید سطح را عوض کنید بدون بازنویسی حلقه.

Real code: CLI

کد واقعی: CLI

The interesting part of cli.py is how little it does. Commands like /memory are still harness concerns (read-only display) — they never enter the loop:

بخش جالب cli.py این است که چقدر کم کار می‌کند. دستورهایی مثل /memory هنوز کار درگاه‌اند (نمایش فقط‌خواندنی): 

# backend/yar/gateway/cli.py (abbreviated)
while True:
    user_message = console.input("you › ").strip()
    if user_message in ("/quit", "/exit"):
        break
    if user_message == "/memory":
        console.print(Panel(_memory_snapshot(yar.conn), ...))
        continue   # no respond() — still harness I/O

    result = yar.respond(user_message, observer=_observer, source="cli")
    console.print(f"yar › {result.reply}")

_observer only prints tool/gate/consolidation events. It does not decide the next tool — that is the loop’s job (lesson 0002).

_observer فقط رویدادها را چاپ می‌کند. ابزار بعدی را انتخاب نمی‌کند — آن کار حلقه است.

Real code: SPA path

کد واقعی: مسیر SPA

The dashboard collects observer events into JSON for the UI, then returns the same LoopResult fields. Streaming is still harness packaging — SSE wraps the same turn:

داشبورد رویدادهای observer را برای UI به JSON جمع می‌کند. استریم هم بسته‌بندی درگاه است — SSE همان نوبت را می‌پیچد: 

# backend/yar/ops/dashboard.py — chat()
result = agent.respond(
    message,
    observer=lambda kind, ev: events.append({"kind": kind, **ev}),
    source="dashboard",
)
return {
    "reply": result.reply,
    "tool_calls": tools,
    "iterations": result.iterations,
    "meta": meta,
    ...
}

On the client, api.chatStream() in frontend/src/lib/api.ts posts to /api/chat/stream and yields SSE events — still moving bytes, not reasoning.

در کلاینت، api.chatStream() به /api/chat/stream پست می‌کند و رویداد SSE می‌دهد — هنوز جابه‌جایی بایت است، نه استدلال.

Skill: draw the boundary

مهارت: مرز را بکشید

For each job, pick Harness or Loop.

برای هر کار، درگاه یا حلقه را انتخاب کنید.

Wrap tool events as SSE for the browser

پیچیدن رویداد ابزار به‌صورت SSE برای مرورگر

Decide to call create_event this iteration

تصمیم به فراخوانی create_event در این تکرار

Handle the /memory slash command

پردازش دستور اسلش /memory

Stop the turn when the model returns no tools

پایان نوبت وقتی مدل ابزاری برنگرداند

Seams, not second implementations

درز، نه پیاده‌سازی دوم

Voice and Telegram gateways are deliberately out of scope in Yar (§13). If you added one, it would still only move text into respond() — same pillar, new adapter. That is how the curriculum stays aligned with the repo’s “one of everything on the default path” rule.

درگاه صدا و تلگرام عمداً خارج از محدوده‌اند (§۱۳). اگر اضافه شوند، باز هم فقط متن را به respond() می‌رسانند — همان ستون، آداپتر جدید.
